# Find it before you write it

The most expensive mistake in this engine is a second document about a topic that
already has one. Retrieval comes before production, every time.

## Inputs

- `INDEX.md` — the generated catalogue of the whole knowledge base (root of the workspace)
- Your profile's **Context to load** list

## Steps

1. **Read `INDEX.md` first.** It lists every document with its title, a one-line
   summary, its owner and when it changed. This is the cheapest possible orientation.
2. **Scan for your topic** across all folders — not just your own. The SEO brief you
   need may sit in `04-content/seo/`, but the claim it rests on lives in
   `02-market-research/`.
3. **Open two or three documents, not twenty.** Pull the ones the index says are
   relevant plus your profile's standing context. Loading everything defeats the point.
4. **If the index has no match, search the text** before concluding nothing exists:
   `grep -ril "<term>" . --include=*.md`
   Filenames lie; contents don't.
5. **Decide, explicitly, one of three things:**
   - **Extend** — a document covers this; add to it or update it.
   - **Create** — genuinely new ground; create one new file in the right folder.
   - **Blocked** — the input you need should exist but doesn't. Say what's missing
     and who owns it, and stop. Do not invent it.
6. **Say what you found** in one line before you start producing, e.g.
   "Found `02-market-research/competitors/acme.md` (updated 2026-06-02) — extending it
   rather than creating a second teardown."

## Quality bar

- [ ] `INDEX.md` was read before any file was written
- [ ] Existing coverage was named explicitly, or its absence was stated
- [ ] No new file duplicates a topic that already has a home
- [ ] Every path referenced came from the index or a text search — none were guessed

## Note

`INDEX.md` is generated by the Admin server after every knowledge change. If it looks
stale, the file's footer shows when it was last built. Never edit it by hand — it
gets overwritten.
